Add a TypeScript extension system (phase 1). Hunk now loads user extensions from `~/.config/hunk/extensions/`, repo-local `.hunk/extensions/` (behind a trust prompt), `[extensions] paths` in config, and a repeatable `--extension` flag (`--no-extensions` disables loading). Extensions export a default factory receiving the `hunkdiff/extension` API and can register themes, file-language mappings, and VCS adapters, transform the loaded changeset, subscribe to lifecycle events (`startup`, `changeset_loaded`, `selection_changed`, `session_reload`, `shutdown`), read their own `[extension.<id>]` config table, and show toast notifications. Hunk's own Jujutsu and Sapling backends are now bundled extensions registered through that same API, so extension VCS adapters are first-class: they can set a detection priority, report untracked paths, and support `--watch` through optional watch signatures and watch plans. `--no-extensions` and `[extensions] enabled = false` scope to user extensions, so jj and Sapling support is never disabled by them. Custom themes are also generalized from the single `[custom_theme]` slot to any number of named `[themes.<id>]` tables. See `docs/extensions.md` for the authoring guide.
